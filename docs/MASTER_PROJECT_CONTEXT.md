# 1. Правила совместной работы

## 1.1 Язык

Общаться с пользователем на русском языке.

## 1.2 Только полные замены

Пользователь не хочет искать отдельные строки и вставлять фрагменты.

Если изменяется событие объекта или Script Asset, нужно выдавать **полную готовую
замену целиком**:

```text
FULL/obj_name_Event_FULL.gml
FULL/script_name_FULL.gml
```

Для нового Script Asset допустима папка:

```text
NEW_SCRIPT/script_name.gml
```

Для нового объекта или нового события:

```text
NEW_OBJECT/obj_name_Create.gml
NEW_EVENT/obj_name_Draw.gml
```

## 1.3 Пакеты

Каждый пакет имеет последовательный номер.

Самый свежий пакет называется:

```text
00_LATEST_<номер>_VetSim_<название>
```

**Без ZIP.** Пользователь всегда берёт файлы из папки, а не из архива.

Предыдущая папка `00_LATEST_...` возвращается к обычному имени с номером (без префикса).
Свежая папка всегда одна и всегда **сверху** списка.

Каждый пакет содержит `README.md` с точным порядком установки.

## 1.4 Не заставлять повторно ставить старые изменения

README нового пакета описывает только новые замены.

## 1.5 Большие события

Большие файлы очищать от мёртвого кода, форматировать, делить на разделы.

## 1.6 Нельзя ломать существующие системы

- медицинские случаи, диагностика, ложные варианты, лечение, назначения;
- владельцы, животные, повторные визиты, регистрация, оплата;
- очередь, склад, пополнение, стационар, чистоту, кадровые навыки;
- карточки (владелец, животное, сотрудник, кандидат);
- дневную статистику, touch-управление;
- справочник болезней, баллы клиники, помещения за деньги, операционную.

## 1.7 Животные

Общие изменения животных выполнять через `par_animals`, а не копировать в `obj_dog_puppy`.

## 1.8 UI для телефона

- Шрифт не меньше, чем у медикаментов на складе (масштаб ≈ 1.3).
- Кнопки крупные (минимум ~52px по высоте), подписи ~1.3.
- Прокрутка + бегунки обязательны везде, где контент может не влезть.
- Зоны кликов всегда совпадают с отрисовкой.

## 1.9 Просьба присылать файлы

Когда меняется скрипт/событие, у которого нет актуальной версии, — просить пользователя
прислать текущий текст из проекта. Пользователь сам файлы не правит — ставит только то,
что присылает агент.

## 1.10 Репозиторий (с 21.08)

Исходники лежат на GitHub: **`https://github.com/Sunlapic/VetSim`**.
Актуальную версию любого файла можно взять оттуда, не спрашивая пользователя.

Важно про репозиторий:
- **нет файла `.yyp`**, комната лежит в `room1/`, хотя внутри `.yy` пути прописаны как
  `rooms/Room1/Room1.yy` — это бэкап исходников, а не открываемый проект;
- `room1/Room1.yy` обновляется редко, расстановка объектов в нём может отставать;
- при загрузке через веб-интерфейс пользователь заливает `.gml`, но часто забывает `.yy` —
  новый объект или новое событие без `.yy` в репозитории «не существует».

# 2. Что уже работает (обзор геймплея)

1. Владельцы с питомцами приходят в клинику.
2. Очередь на регистрацию; админ или игрок регистрирует клиента.
3. Waiting area; монитор очереди.
4. Игрок вручную берёт пациента на приём (или NPC-врач берёт сам).
5. Кабинеты через точки: владелец/питомец/врач идут к столу, питомец на стол.
6. Диагностика и назначения через планшет; ложные варианты; подтверждение диагноза.
7. Процедуры выполняет игрок или ассистент.
8. Тяжёлый пациент (<50% состояния) — в стационар (4 койки).
9. **Хирургический случай — тоже в стационар, оттуда его забирают в операционную.**
10. Чек владельца (работа + препараты отдельно); оплата; зарплата в полночь.
11. Найм персонала; кандидат ждёт 1 игровой час и уходит.
12. Баллы клиники за полное выздоровление; прокачка за баллы.
13. Помещения за деньги (кабинеты приёма).
14. Справочник болезней (открывается за идеальный ручной приём).
15. 50 болезней (11 старых + 39 новых, только собаки), из них 6 хирургических.
16. Главный склад — объёмный стеллаж 4×12: цветные 3D-кубики, таблички, лимит закупки.

## Правило повторяемости лечения (важно, пакет №171)

В связке болезнь → лечение (`db_init_disease_links`) есть флаг
`repeat_until_recovered`. Его читает `case_build_next_procedure_assignments`:

```gml
if (_repeat_until_recovered) {
    if (_case.condition < 100) array_push(_result, _action_id);   // повторять
} else {
    if (_done_count < _need_count) array_push(_result, _action_id); // один раз
}
```

**У каждой болезни должно быть хотя бы одно повторяемое действие**, иначе пациент
застревает в стационаре ниже 100% навсегда: список назначений пустеет, повторять
нечего, выписки нет. Пакет №171 закрыл две такие дыры (`disease_foreign_body_ear` →
`treat_ear_drops`, `disease_periodontitis` → `treat_antibiotic`).

## Пакет №170: стационар как предоперационная палата

Пять точечных изменений, всё остальное не тронуто:

| Где | Что |
|---|---|
| `inpatient_can_admit` | пациент с `or_waiting_surgery` кладётся при **любом** состоянии |
| `inpatient_controller_step` | в самом начале: `or_surgery_hold` → палата на паузе, койка держится за пациентом |
| `inpatient_apply_treatment_action` | хирургические действия палата **не выполняет** |
| `inpatient_assign_treatments` | хирургия вырезается из цикла назначений палаты |
| выписка (2 места) | пока `or_waiting_surgery` — выписки нет даже при 100% |

Без последнего пункта пациента выписывали бы до операции; без третьего перелом
«лечился» бы уколом прямо на койке.

## Разворот и глубина (пакеты №75, №76)

- `inpatient_system` назначает `assigned_table = _ward.ward_table` персоналу при
  `inpatient_prescribing` (врач) и `inpatient_treating` (ассистент), сбрасывает после.
- `par_staff → Step` и `End Step` включают разворот и глубину `assigned_table.depth - 3`.
- **Важно:** бригаде операционной `assigned_table` НЕ выдаётся — иначе сторож зависаний
  в `par_staff → Begin Step` (раздел 5.1) сбросит сотрудника в `idle` прямо во время
  операции. Поэтому глубина и разворот у операционного стола считаются вручную
  (см. раздел 16).

# 16. Операционная (пакеты №108–113, №161–171)

## Схема (актуальная, пакет №170)

```
Приём: терапевт ставит диагноз и назначает операцию
  → терапевт увозит пациента в СТАЦИОНАР, владелец уходит домой
  → пациент лежит на койке, над ним «ЖДЁТ ОПЕРАЦИЮ»
  → освободилась операционная и собралась бригада
  → ассистент забирает пациента с койки, на койке «НА ОПЕРАЦИИ»
  → операционный стол → операция (шкала)
  → пациента возвращают на ТУ ЖЕ койку
  → палата долечивает, возвращается владелец, оплата
```

Койка **не освобождается** на время операции: она закреплена за пациентом.

## Данные (пакет №108)

- Препараты: `item_anesthetic` ($70), `item_surgical_kit` ($120). Всего 44.
- 6 действий с `is_surgery : true`, `room_id : "room_operating"`:

| Действие | Цена | Δсостояния | Болезнь | Терапия после |
|---|---|---|---|---|
| `treat_osteosynthesis` | 250 | +20 | перелом лапы | обезболивание (повтор) |
| `treat_wound_surgery` | 150 | +14 | рваная рана | обезболивание (повтор) |
| `treat_surgical_hemostasis` | 180 | +18 | кровотечение | капельница (повтор) |
| `treat_foreign_body_removal` | 200 | +15 | инородное тело в ухе | ушные капли (повтор с №171) |
| `treat_cystotomy` | 350 | +22 | мочекаменная | диета (повтор) |
| `treat_tooth_extraction` | 120 | +12 | пародонтит | антибиотик (повтор с №171) |

## Бригада

- Врач в карточке выбирает `ОПЕРАЦИОННАЯ: ХИРУРГ` или `ОПЕРАЦИОННАЯ: АНЕСТЕЗИОЛОГ`,
  ассистент — `ОПЕРАЦИОННАЯ`. Хранится как `workplace_id = "operating"` + `operating_role`.
- Допуск: Хирургия / Анестезиология / Процедуры **≥ 3**.
- Игрок автоматически заменяет отсутствующего хирурга или анестезиолога.
- Время = t(Хирургия) + t(Анестезиология) + t(Процедуры), `t(lvl) = max(2, 22 − 2×lvl)`.
- Риска нет, операция всегда успешна.

## Стулья ожидания (пакет №161, №164)

- `obj_operating_seat` — без спрайта, без родителя, solid = нет.
  Create: `visible = false; or_seat_role = ""; ward_slot_id = 0;`
  В Creation Code инстанса: `or_seat_role = "surgeon" / "anesthetist" / "assistant"`.
- Свободная бригада (`operating_idle`) сидит на стульях (`spr_human_FR_sit`, флаг `or_seated`).
- Если `or_seat_role` не проставлен — стулья раздаются по порядку ролей (№162).
- Раздача одним проходом, двое на один стул не идут (№164).

## Свободный ассистент операционной (пакет №169)

Пока операционная пуста, раз в секунду пробует взять хозяйственное дело:
- пополнение шкафов — `assistant_try_take_restock_job()` (состояние `idle` подставляется
  на время вызова);
- уборка — `dirt_send_assistant_to()` по ближайшему свободному пятну.

Появилась операция — `operating_assistant_abort_chore()` бросает дело: грязь
освобождается, товар из рук возвращается на склад, бронь стола снимается.

## Фазы контроллера

```
empty → escort → transfer → operating → finishing → returning → empty
```

| Фаза | Что происходит |
|---|---|
| `empty` | `operating_try_start_pending()` молча ищет пациента с `or_waiting_surgery` |
| `escort` | ассистент идёт к пациенту в палату, врачи параллельно встают на свои точки |
| `transfer` | пациент идёт на операционный стол, бригада ждёт **стоя** (`or_working = false`) |
| `operating` | шкала, бригада работает руками (`or_working = true`) |
| `finishing` | применяется результат, пациента отправляют обратно на койку |
| `returning` | ждём, пока пациент ляжет; затем `or_surgery_hold = false`, палата просыпается |

Страховочные таймауты: escort 20с, transfer 40с, returning 40с.

## Постановка на места, глубина, разворот

- Маршрут — `operating_walk_actor_to()`: перестраивается при смене цели, при обрыве
  пути и раз в секунду. `inpatient_ensure_walk` не годится: она строит путь только
  когда сотрудник полностью остановлен, из-за чего персонал «замирал» (№162).
- Достижимая клетка — `operating_seat_reachable_target()`: кольца 20/32/48/64/88 в
  8 направлениях. Точки стоят вплотную к столу, их клетки закрыты в mp_grid (№164, №167).
- Финальная доводка: ближе 28px сотрудник ставится точно в координату точки (№167).
- **Глубина:** хирург и ассистент `стол.depth − 3` (перед столом), анестезиолог
  `стол.depth + 3` (за столом). Считается в End Step, потому что `assigned_table`
  бригаде не выдаётся (№166, №167).
- **Разворот:** `operating_face_work_table()` повторяет формулу `par_staff` (раздел 4):
  выше стола — лицом по знаку, ниже — наоборот (№169).

## Дрейф пациента (важно, пакет №168)

`move_towards_point` (запасной путь, когда `mp_grid_path` не построил маршрут) задаёт
встроенную `speed` — и **никто её не обнуляет**, `path_end()` к ней отношения не имеет.
Из-за этого животное дрожало сидя на столе и «уезжало» с койки по комнате.

`operating_pet_stop_drift()` гасит `speed`, `hspeed`, `vspeed`, путь и `is_walking`.
Вызывается при укладке на стол, всю операцию и при укладке на койку.

Плюс пациент **сходит** со стола на запомненную точку пола (`or_pet_floor_x/y`) —
маршрут из клетки стола не строится, она закрыта в mp_grid.

## Отрисовка

- Одна табличка со шкалой над столом в стиле приёма (`actor_draw_action_progress`):
  рамка, бумага, название операции, шкала под текстом. Только в фазе `operating`.
- `operating_draw_ward_labels()` — «ЖДЁТ ОПЕРАЦИЮ» над пациентом и «НА ОПЕРАЦИИ»
  над койкой.
- Сидящие рисуются ветками сидения в `obj_staff_doctor → Draw` и
  `obj_staff_assistant → Draw` (новое событие, №163): фиксированный скейл 0.5,

  владельцев на диванах в `par_visitors → Draw`.

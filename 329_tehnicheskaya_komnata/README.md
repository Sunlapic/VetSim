# Пакет №329 — техническая комната, честная «Новая игра», диагностика с указанием клиники

Устанавливается **вместо** одноимённых файлов из пакетов №325–№328.
Все файлы полные — заменяются целиком.

---

## Что меняет

### 1. Room1 больше не участвует в игре

Room1 остаётся базой объектов, из которой расставляются клиники, но в
игровом цикле её нет:

- **Убрана клавиша R** — перехода в тестовую комнату больше нет
  (`obj_Render → Step`).
- **Защита в `obj_Render → Create`.** Если игра запустилась в комнате,
  которая не принадлежит ни одной клинике, `obj_Render` делает одно:
  пишет строку в консоль и уводит игру в клинику №1. Всё остальное в
  этой комнате не запускается — ни день, ни деньги, ни персонал,
  ни будильник загрузки сохранения.
- **Ничего из технической комнаты никуда не уходит.** Сохранение при
  выходе из неё не пишется (флаг `clinic_room_transition`), персонал в
  карман клиники не сворачивается, диагностика в ней молчит.
- Инстансы технической комнаты уничтожать не нужно: они исчезают
  вместе с комнатой. **Специально не вызывается
  `instance_destroy(par_staff)`** — `obj_player` наследуется от
  `par_staff` (проверено по `objects/obj_player/obj_player.yy`,
  `parentObjectId : par_staff`), и такой вызов убил бы игрока.

В консоли при запуске будет одна строка:

```
[CLINIC START] Комната Room1 не принадлежит ни одной клинике — в игре
не участвует. Переход в клинику №1 (rm_clinic_1).
```

### 2. «Новая игра» начинает всё с нуля

`save_slot_new_game()` теперь:

1. удаляет рабочий файл `vetsim_save.json`;
2. вызывает `new_game_reset()` — сбрасывает **все четыре кармана
   клиник** (персонал, склад, построенные помещения, улучшения,
   репутация, картотека), сеть клиник (`clinics_spec()` — куплена
   только клиника №1), деньги, баллы, репутацию, чистоту, день и
   время, картотеку клиентов (`db_clients_init()`);
3. **проверяет**, что файл действительно удалён, и пишет об этом;
4. вызывает `game_restart()` — он единственный вычищает несколько сотен
   `global`, накопленных за день игры.

После перезапуска игра встаёт в клинику №1 (защита из пункта 1).

Старт: **100 000 денег, 500 баллов, репутация 0, день 1** — по твоему
ответу, тестовый режим. Значения лежат в одном месте:

```
NEW_GAME_START_MONEY  100000     ← скрипт vet_new_game
NEW_GAME_START_POINTS 500        ← скрипт vet_new_game
```

Запасные значения продублированы в `obj_Render → Create` и в
`save_system` (2 места) — там тоже теперь 500. Обычный старт партии
(15 000 / 0) вернуть, поменяв эти значения.

В консоли:

```
[НОВАЯ ИГРА] Старт с нуля: клиника №1, деньги 100000, баллы 500,
репутация 0, день 1.
[SLOT] Файл сохранения удалён — старт с нуля.
[SLOT] Новая игра — перезапуск.
```

### 3. В диагностике видно, в какой клинике проблема

Каждое предупреждение о расстановке теперь начинается с клиники и
комнаты:

```
[TABLE] Клиника №2 «Районная лечебница» · rm_clinic_2 · стол в позиции
(1200,840) без exam_slot_id — считается кабинетом 1. …

[INPATIENT] Клиника №3 «Городской ветцентр» · rm_clinic_3 · койка 104
не собрана. Не хватает: точка ассистента, точка владельца. Проверь слот
у ВСЕХ объектов этой койки: у контроллера и стола — exam_slot_id = 104;
у точек — ward_slot_id = 104.

[CABINET] Клиника №1 «Каморка на окраине» · rm_clinic_1 · шкаф в
позиции (…) не имеет exam_slot_id! …

[CABINET WARNING] Клиника №2 «Районная лечебница» · rm_clinic_2 · два
шкафа имеют exam_slot_id = 3

[STOCK] Клиника №4 «Клиника у парка» · rm_clinic_4 · шкаф слота 2 не
найден для …
```

### 4. Новая проверка состава комнаты

`obj_Render → Alarm 2` (новое событие) один раз за вход в комнату
проверяет состав и печатает ровно то, чего не хватает:

```
[ПРОВЕРКА] Клиника №3 «Городской ветцентр» · rm_clinic_3 · кабинет
приёма 2: нет объекта точка владельца (obj_exam_point_owner). Поставь
объект и пропиши exam_slot_id = 2; в Creation Code инстанса.

[ПРОВЕРКА] Клиника №3 «Городской ветцентр» · rm_clinic_3 · койка 105:
нет объекта точка ассистента стационара (obj_inpatient_point_assistant).
Поставь объект и пропиши ward_slot_id = 105; в Creation Code инстанса.

[ПРОВЕРКА] Клиника №3 «Городской ветцентр» · rm_clinic_3 · ИТОГО:
найдено проблем — 7.
```

Что проверяется:

- системные объекты: `obj_Render`, `obj_UI_HUD`, `obj_UI_Tablet`,
  `obj_player`, `obj_monitor`, `obj_storage_main`,
  `obj_candidate_spot`, `obj_cleanliness_controller`;
- точки ожидания (`obj_wait_spot`);
- четыре маркера зон уборки;
- столы без `exam_slot_id` (у `obj_table` слот по умолчанию 1, у
  `obj_table_1` — 2, поэтому стол молча приписывается чужому кабинету);
- **каждый открытый кабинет приёма** — 6 объектов на слот;
- регистратура 1 и 2 — 3 объекта на слот;
- если палата куплена: общий набор стационара (3 объекта) и **каждая
  открытая койка** — 7 объектов на слот;
- если операционная куплена: 7 объектов операционной и 3
  послеоперационной;
- дубли: два объекта одного типа на одном слоте — перечисляются
  инстансы с координатами.

Проверка печатается **всегда**, не только в режиме отладки (по твоему
выбору). В технической комнате она молчит. Список проверенных комнат
обнуляется в Room Start, так что при переезде между клиниками каждая
проверяется заново.

Проверка работает и после загрузки сохранения: она смотрит только на
расстановку объектов в комнате, а не на персонал, поэтому сейв на неё
не влияет.

  технической комнате не уничтожаются кодом.

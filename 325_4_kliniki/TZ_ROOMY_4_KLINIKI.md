# ТЗ: состав комнат rm_clinic_1 … rm_clinic_4

Состав взят из рабочей тестовой комнаты `Room1` — те же объекты и те же
значения `exam_slot_id`, которыми игра уже умеет пользоваться.

**Общее правило:** `exam_slot_id` задаётся в Creation Code **каждого**
объекта, относящегося к этому кабинету/койке. У всех объектов одной
группы значение одинаковое.

## Номера слотов

| Группа | Слоты | Комментарий |
|---|---|---|
| Кабинеты приёма | `1`, `2`, `3`, `4`, `5`, `6` | слот 1 есть всегда, остальные покупаются |
| Койки стационара | `101` … `108` | `101` и `102` открываются вместе с палатой, `103`+ покупаются поштучно |
| Операционная | `201` | оперблок |
| Реанимация после операции | `202` | кровать восстановления |

## Кабинет приёма N (N = 1…6)

У каждого кабинета свой набор, `exam_slot_id = N`:

| Объект | Штук |
|---|---|
| `obj_table` | 1 |
| `obj_exam_point_doctor` | 1 |
| `obj_exam_point_owner` | 1 |
| `obj_exam_point_pet_floor` | 1 |
| `obj_exam_point_pet_table` | 1 |
| `obj_storage_cabinet` | 1 |

# rm_clinic_1 — «Каморка на окраине»

**Потолки:** кабинеты **2**, коек **нет**, операционной **нет**,
склад маленький, найм **4**.

Ставить сразу (остальное игрок докупит, но объекты в комнате должны
быть — покупка только открывает уже расставленное):

- Кабинет **1**: полный набор кабинета, `exam_slot_id = 1`
- Кабинет **2**: полный набор кабинета, `exam_slot_id = 2`
- Регистратура: слоты `reception_slot_id = 1` и `2`
- Общее: `obj_wait_spot` ×4, раковины, чистота, `obj_candidate_spot`,
  `obj_storage_main`, `obj_player`, `obj_Render`, `obj_UI_HUD`,
  `obj_UI_Tablet`, `obj_monitor`

**Не ставить:** койки, операционную. Комната самая маленькая.

# rm_clinic_2 — «Районная лечебница»

**Потолки:** кабинеты **3**, койки **2**, операционной **нет**,
склад средний, найм **7**.

- Кабинеты **1, 2, 3**: `exam_slot_id = 1, 2, 3`
- Койки **101, 102**: `exam_slot_id = 101, 102` + общие объекты
  стационара (`obj_inpatient_cabinet`, `obj_inpatient_doctor_chair`,
  `obj_inpatient_point_doctor_rest`)
- Регистратура: слоты 1 и 2
- Общее: `obj_wait_spot` ×5, остальное как в клинике №1

**Не ставить:** койки 103+, операционную.

# rm_clinic_4 — «Клиника у парка»

**Потолки:** кабинеты **6**, койки **8**, операционная **есть**,
склад большой, найм **17**.

- Кабинеты **1 … 6**: `exam_slot_id = 1 … 6`
- Койки **101 … 108**: `exam_slot_id = 101 … 108` + общие объекты
  стационара
- Операционная: `exam_slot_id = 201` (оперблок) и `exam_slot_id = 202`
  (кровать восстановления)
- Регистратура: слоты 1 и 2
- Общее: `obj_wait_spot` ×6, остальное как в клинике №1

Это единственная клиника с операционной — только здесь операционный
кейс может быть выполнен.

---

## Важно

- Лишние слоты в комнате не страшны: игра не откроет кабинет или койку
  сверх потолка клиники, даже если объекты расставлены. Но и купить
  несуществующий слот нельзя — объекта просто не будет.
- Имя комнаты должно совпадать точно: `rm_clinic_1` … `rm_clinic_4`.
  По этим именам код понимает, в какой клинике находится игрок
  (`clinic_room_owner()`), и по ним же происходит переход
  (`clinics_enter` → `room_goto`).
- `Room1` остаётся тестовым полигоном: при старте игры `obj_Render`
  уводит игрока в комнату клиники №1.

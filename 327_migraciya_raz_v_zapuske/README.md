# Пакет №327 — миграция сети выполняется один раз за запуск

> **Пакет закрыт.** Приставка `00_LATEST_` снята: актуальный пакет
> теперь `00_LATEST_328_koyki_bez_spama`.

## Что исправлено

В консоль на каждом кадре писалось:

```
[CLINICS] Сеть приведена к четырём клиникам (пакет №325)
```

Сотни одинаковых строк за минуту.

**Причина.** `clinics_init()` вызывают не только при старте, но и из
`obj_UI_HUD → Step` (строки 922 и 1540), то есть каждый кадр. Внутри
`clinics_init()` стояло: если `global.clinics` уже есть — запустить
`clinics_migrate_to_spec()`. После первого же запуска список клиник
всегда есть, поэтому миграция выполнялась на каждом кадре: заново
собирала `global.clinics` и писала в консоль.

Это был не только шум: каждый кадр пересоздавались четыре структуры
клиник, а значит любые изменения в них, сделанные между кадрами,
затирались эталоном.

**Что сделано.** Добавлен флаг `global.clinics_spec_migrated`. Миграция
выполняется один раз за запуск игры, остальные вызовы `clinics_init()`
проходят дальше, ничего не пересобирая.

## Заодно в логе: это не ошибка кода

```
[TABLE] Стол в позиции (978,924) без exam_slot_id — считается кабинетом 1.
[TABLE] Стол в позиции (1259,908) без exam_slot_id — считается кабинетом 1.
```

Два объекта `obj_table` в комнате `rm_clinic_1` стоят без Creation Code,
поэтому игра считает их оба столом кабинета 1. Чтобы второй стол стал
кабинетом 2, добавьте в Creation Code инстанса:

```gml
exam_slot_id = 2;
```

То же самое касается всех объектов группы: у шести объектов кабинета 2
должно стоять `exam_slot_id = 2;`. Состав — в
`SOSTAV_KOMNAT_PO_KLINIKAM.md`.
